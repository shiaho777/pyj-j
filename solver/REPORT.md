## 战场 1:v2 两池套利——锯齿结构与诚实的结论

基准:50 个真实尺度套利机会($50k–$100M 流动性,0.61–5% 失衡)。

### 发现:EVM 利润曲线是锯齿,不是光滑抛物线

在真实池子尺度(WETH 18 位 / USDC 6 位)下,整数利润 P(x) 的结构是:

- **齿内**:斜率精确为 −1——每多投 1 wei,利润少 1 wei
- **齿间跳变**:每当 `evm_out` 跨过一个输出单位边界,利润**跳升**一整个齿高

实测($100M 池,1.47% 失衡):齿距 196,140,415 wei,齿高 333,346,088 wei
(即跨过一次齿边界,净赚 137,206,172 wei)。**所有邻近齿顶的利润彼此只差
≤1 wei** —— 这意味着:

> **最优套利规模 = 跳到某个齿顶(每个齿的第一个可行 x),而不是连续最优
> 点的整数化。** 闭式解和 float64 都给出"齿中间"的答案,白白损失高达
> 一个完整齿高。

## 发现 2:O(1) 精确算法(无搜索、无 float)

```
base_x = (isqrt(alpha*beta) - beta) // delta     # 连续最优,整数 sqrt
k0     = evm_out(base_x)                          # 当前齿
x_k    = ceil(k*1000*a0 / (997*(a1-k)))           # 每个齿顶的解析反函数
最优   = argmax evm_profit_two over 齿顶 k0-3..k0+6(一次重定向)
```

基准结果(50 案例全部命中暴力真值):

| | float64 机器人 | 精确求解器 |
|---|---|---|
| 落在齿顶 | 0 / 50 | **50 / 50** |
| 利润 = 真值 | 0 / 50 | **50 / 50** |
| 溢出/失败 | 依赖重缩放补丁 | 无(纯整数) |

## 发现 3(诚实):损失规模由**中间代币的美元粒度**决定

float64 的每笔损失 ≈ 齿高 ≈ 中间代币 1 个最小单位的美元价值 × ~1.5:

| 中间代币 | float64 每笔损失 | 套利总利润 | 损失占比 |
|---|---|---|---|
| 6 位小数 USDC($1) | $0.000001 | $99.70 | ~0% |
| 8 位小数 WBTC($60k) | $0.0002 | $99.70 | ~0% |
| 2 位小数($1000 单价) | **$3.17** | $99.70 | **3.2%** |
| 0 位小数($1000 单价) | **$963.20** | $99.70 | **963%** — 整笔亏没 |

**结论(不夸大)**:
- 对主流 18/6 位小数对(WETH/USDC),float64 的次优性经济上可忽略。
  诚实地承认:v2 双池套利**不是**精确内核的杀手级场景。
- 但当路径经过**粗粒度代币**(低小数位、高单价——真实存在:某些
  L2 上的 2 位小数稳定币、整数化 NFT 碎片、低精度包装资产)时,
  float64 会把利润的 3%–963% 留在桌上,而精确求解器拿满。
- 损失公式:`损失_usd ≈ 1.5 × 中间代币单价 / 10^小数位`。
  这是一个可预测、可审计的风险陈述——比"我们的更精确"这种空话有用。

## 对产品方向的含义

1. **优化型场景**(v2 双池):精确内核有结构性优势(100% 齿顶命中)
   但主流币对经济意义小。**约束型场景**(下一阶段)才是真战场:
   批量拍卖/CoW 求解里,解必须满足**严格整数约束**(用户限价、
   守恒方程)——float64 差 1 wei 就是整个解被拒绝(revert/出局),
   损失的不是利润,是整场竞标。这正是精确内核不可替代的地方。
2. 锯齿结构和 O(1) 齿顶算法本身是可发表的洞察——市面上的 v2
   套利教程全部教连续闭式解 + 整数化,没人提齿结构。

## 战场 2:v3 tick 数学——入场券,不是优势

`v3math.py`:SqrtPriceMath + TickMath 的纯整数实现,舍入方向与 Solidity
逐位一致。`test_v3.py` 24/24:独立 Fraction 参考对拍、守恒律 L²=xy、
amount delta = 储备差、目标价截断、双向交换。

诚实边界:链上 TickMath 是平方表近似,极值 tick 与精确 floor 有 wei 级
偏差(MIN tick 差 2 wei);偶数 tick 我们是可证精确的纯整除。生产必须
从链上读 tick 数据。

结论:链上本来就是整数运算,**做对的 v3 模拟器是入场券**。它的价值
在于支撑下一步:跨 tick 撮合与批量结算的约束验证。

## 战场 3:批量拍卖(CoW)——精确内核的主场

`cow.py`:把 CoW 批量拍卖化归到整数核心——限价单(部分成交,18 位
小数整数单位)、统一清算价撮合、**纯整数法官**模拟链上合约:

- (L) 限价:`b_i·S_i ≥ B_i·f_i`(逐单)
- (C) 守恒:每代币 卖出 == 买入(**精确相等**)

差 1 wei,整个解 revert = 竞标输给对手 + gas + 声誉。

### 结果(200 批随机紧价差订单,seed 7)

| | float64 求解器 | 精确求解器 |
|---|---|---|
| 链上有效 | 137/200(68%) | **200/200(100%)** |
| REVERT | **63(31.5%)** | **0** |
| 成交量 | 63,780 A-units | **89,509 A-units** |
| 用户盈余 | 82.94 A-units | **124.97 A-units** |

失败模式全部是"限价差几个 wei":`int(ratio × fill)` 向下舍到必需的
ceil 之下。且 revert 的批次偏小成交量——小订单的 float 相对误差更
大,与战场 1 的粒度缩放律自洽。

### 为什么这里不同

v2 套利里 float64 只是**少赚**(利润曲线平顶);批量拍卖里 float64
是**出局**(整数约束硬边界)。优化问题对精度宽容,**约束问题对精度
零容忍**——这就是精确内核的产品定位。

## 战场 4(2026-09-08 追加):主网真实验证 —— 法官 vs CoW 生产合约

`mainnet.py`:从公共 RPC 拉取最近 30 个区块,解码真实 CoW 结算交易
(GPv2Settlement `0x9008…b41`,2024 版 `settle()` 签名 `0x13d79a0b`,
纯 Python ABI 解码器),用**我们的整数法官**复验每一笔交易的限价约束:

```
execBuy = ceil(execSell × price[sellIdx] / price[buyIdx])   # 与合约一致的舍入
(L)     execBuy × sellAmount ≥ buyAmount × execSell         # 同 cow.py
```

### 结果(19 笔结算,21 笔交易)

| | 数量 | 含义 |
|---|---|---|
| 法官 PASS + 链上成功 | **20** | 语义一致 ✓ |
| 法官 PASS + 链上 revert | 1 | revert 在订单约束**之外**(下述) |
| **真分歧**(法官 FAIL + 链上成功) | **0** | **法官与生产合约的约束核心等价** |

### 那笔 revert 的解剖(cast run 链上回放)

`0x6b23…dfcb` 链上 revert 原因:**"Insufficient ETH balance for
exchange"**——交互层(交易所流动性)余额不足,与订单限价无关。我们的
法官对它的限价判 PASS,与链上约束一致。

**生产含义**:求解者烧了 368,731 gas 在一笔注定 revert 的结算上。
一个包含交互层的**精确预检模拟器**(我们的 v2/v3 EVM 精确数学 +
整数法官)能在提交前抓住它——这就是产品:提交前预检,不烧废 gas,
不掉竞标。

### 技术细节(踩坑记录)

- 动态元组数组的 ABI 编码是 `[len][每元素偏移][元素数据]`,不是
  连续拼接
- 地址在字内右对齐(切片 +12 字节)
- 链上 TickMath 是平方表近似,极值 tick 有 wei 级偏差(生产从链上读)
- 公共 RPC(publicnode)对默认 urllib UA 返回 403,需自定义 UA

### 环型守恒分析(USDC↔WBTC 环,真实数据)

- 环的可提取总盈余:15,678 WBTC-units(≈$1.9,价格价差 0.0012662–
