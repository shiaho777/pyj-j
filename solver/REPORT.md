# Solver Recon Report — v2 两池套利：精确 vs float64

日期:2026-09-08 · 基准:`solver/bench_arb.py`(50 个真实尺度套利机会,$50k–$100M 流动性,0.61–5% 失衡)

## 发现 1:EVM 利润曲线是锯齿,不是光滑抛物线

在真实池子尺度(WETH 18 位 / USDC 6 位)下,整数利润 P(x) 的结构是:

- **齿内**:斜率精确为 −1——每多投 1 wei,利润少 1 wei
- **齿间跳变**:每当 `evm_out` 跨过一个输出单位边界,利润**跳升**一整个齿高

实测($100M 池,1.47% 失衡):齿距 196,140,415 wei,齿高 333,346,088 wei
(即跨过一次齿边界,净赚 137,206,172 wei)。**所有邻近齿顶的利润彼此只差
≤1 wei** —— 这意味着:

> **最优套利规模 = 跳到某个齿顶(每个齿的第一个可行 x),而不是连续最优
> 点的整数化。** 闭式解和 float64 都给出"齿中间"的答案,白白损失高达
> 一个完整齿高。

## 发现 2:O(1) 精确算法(无搜索、无 float)

```
base_x = (isqrt(alpha*beta) - beta) // delta     # 连续最优,整数 sqrt
k0     = evm_out(base_x)                          # 当前齿
x_k    = ceil(k*1000*a0 / (997*(a1-k)))           # 每个齿顶的解析反函数
最优   = argmax evm_profit_two over 齿顶 k0-3..k0+6(一次重定向)
```

基准结果(50 案例全部命中暴力真值):

| | float64 机器人 | 精确求解器 |
|---|---|---|
| 落在齿顶 | 0 / 50 | **50 / 50** |
| 利润 = 真值 | 0 / 50 | **50 / 50** |
| 溢出/失败 | 依赖重缩放补丁 | 无(纯整数) |

## 发现 3(诚实):损失规模由**中间代币的美元粒度**决定

float64 的每笔损失 ≈ 齿高 ≈ 中间代币 1 个最小单位的美元价值 × ~1.5:

| 中间代币 | float64 每笔损失 | 套利总利润 | 损失占比 |
|---|---|---|---|
| 6 位小数 USDC($1) | $0.000001 | $99.70 | ~0% |
| 8 位小数 WBTC($60k) | $0.0002 | $99.70 | ~0% |
| 2 位小数($1000 单价) | **$3.17** | $99.70 | **3.2%** |
| 0 位小数($1000 单价) | **$963.20** | $99.70 | **963%** — 整笔亏没 |

**结论(不夸大)**:
- 对主流 18/6 位小数对(WETH/USDC),float64 的次优性经济上可忽略。
  诚实地承认:v2 双池套利**不是**精确内核的杀手级场景。
- 但当路径经过**粗粒度代币**(低小数位、高单价——真实存在:某些
  L2 上的 2 位小数稳定币、整数化 NFT 碎片、低精度包装资产)时,
  float64 会把利润的 3%–963% 留在桌上,而精确求解器拿满。
- 损失公式:`损失_usd ≈ 1.5 × 中间代币单价 / 10^小数位`。
  这是一个可预测、可审计的风险陈述——比"我们的更精确"这种空话有用。

## 对产品方向的含义

1. **优化型场景**(v2 双池):精确内核有结构性优势(100% 齿顶命中)
   但主流币对经济意义小。**约束型场景**(下一阶段)才是真战场:
   批量拍卖/CoW 求解里,解必须满足**严格整数约束**(用户限价、
   守恒方程)——float64 差 1 wei 就是整个解被拒绝(revert/出局),
   损失的不是利润,是整场竞标。这正是精确内核不可替代的地方。
2. 锯齿结构和 O(1) 齿顶算法本身是可发表的洞察——市面上的 v2
   套利教程全部教连续闭式解 + 整数化,没人提齿结构。
